SECTION 1 · HISTORICAL BASELINE
Where We Started: Six Failure Modes
GLM-OCR Local Crash
Missing torchvision/weights silently degraded every page to bare PyMuPDF text — no tables, no figures.
GLM-OCR Visual Blindness
algorithms/image_extraction/glm_ocr never existed, so the OCR backend had no image_extractor at all.
Baseline Vector Blindness
page.get_images() returned zero on vector-drawn charts and logos, skipping figure captioning entirely.
Reader Context Starvation
A 4,000-character cap truncated multi-chunk figure captions before they reached the LLM reader.
Rate Limit Throttling
gemini-2.5-flash's 20 req/day free-tier quota triggered repeated 429 Resource Exhausted errors.
TAT-DQA 100% Smoke-Test Mirage
A single-document candidate pool (Total chunks: 1) made Hit@1 = 100% mathematically guaranteed.

SECTION 1 · HISTORICAL BASELINE
How Bad It Actually Was
6.1%
Initial UniDoc visual-query score
Queries 1–5 in finance.json are 100% image-only visual queries — yet the legacy runner scored just 6.1% in aggregate.
100%
TAT-DQA smoke-test mirage
--limit 5 indexed a single document, so the retrieval pool held only that one doc — Hit@1 was guaranteed, not earned.
ROOT CAUSES BEHIND THE 6.1% SCORE
Vector Graphics Blindness
Charts and logos in modern PDFs are drawn with vector commands, not raster Image XObjects — page.get_images() saw nothing.
Context Starvation
Figure captions landing in chunk 6 or 7 were cut off by the reader's 4,000-character truncation limit.
Imprecise Prompting
The generic “Describe this figure” prompt produced prose that omitted exact numbers and axis labels.
Stale Negative Cache
Cached NOT_FOUND answers kept returning even after the missing context was finally supplied.

SECTION 2 · ENGINEERING RESPONSE
The Four Fixes That Mattered Most
Vector Drawing Density Scanner
Pages with ≥5 vector drawings or chart keywords are rendered at 150 DPI and routed to the visual figure extractor — catching charts with zero raster objects.
Verbatim Multimodal Prompting
Replaced “Describe this figure” with a transcription prompt forcing exact labels, axes, and numbers instead of subjective prose.
Reader Context Expansion
Truncation threshold raised from 4,000 to 36,000 characters, so tabular context and visual captions reach the LLM reader together.
Gemini Model Prioritization
Fallback order set to gemini-3.5-flash-lite → gemini-flash-lite-latest → gemini-3.6-flash, eliminating all 429 quota errors.

SECTION 3 · METHODOLOGY
How We Measure Success
Retrieval Layer
Hit@1
Top-ranked chunk matches the gold document
Hit@5 / Hit@10
Gold document appears in top 5 / top 10
MRR
Average of 1 / rank of the first relevant hit
NDCG@10
Ranking quality, discounted by position
True E2E QA (TAT-DQA)
Exact Match
Normalized string equality vs. gold
Numeric EM
Equality after stripping $, commas, units
Set EM
All expected spans present, any order
Token F1 / Semantic
Bag-of-word overlap / embedding similarity
Headline Score
0.30·Retrieval + 0.35·F1 + 0.35·Numeric EM
LLM-as-a-Judge (UniDoc)
Factual Accuracy
Correctness vs. gold facts in the source
Completeness
All requested entities/dates addressed
Answer Relevance
Directly answers, no digression
Overall Judge Score
Holistic blend of the three dimensions

SECTION 6 · CLOSING
Key Engineering Takeaways
Multimodal Parity Achieved
GLM-OCR now matches the reformed baseline's visual understanding — 95.0% accuracy transcribing vector charts, line graphs, and logos on backing PDFs.
Zero Quota Exhaustion
Reprioritizing to gemini-3.5-flash-lite and gemini-flash-lite-latest eliminated every 429 Resource Exhausted error across both benchmarks.
Multi-Document Robustness
The expanded 30-query, multi-document TAT-DQA test held 90.0% Top-1 accuracy — confirming RRF hybrid retrieval scales past single-doc smoke tests.
Next: extend the 30-query multi-document protocol to UniDoc-Bench, and resolve the Q2 dataset mislabeling.
